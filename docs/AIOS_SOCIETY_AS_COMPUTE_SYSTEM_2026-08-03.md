# 사회를 컴퓨트 시스템으로 — 무엇을 매핑하고, 무엇을 매핑하면 안 되는가 (2026-08-03)

founder 질문: *"그리고 이걸 어떻게 compute system으로 바꿀 수 있는가."*
방법: 프론티어 어휘 정찰(`docs/AIOS_FRONTIER_VOCABULARY_2026-08.md`) → 그 어휘로 council →
아래 설계. **빌드 착수 전 문서이며, N1(G5) 게이트가 여전히 앞선다.**

## 0. 한 줄 답

> **우리가 지어야 할 컴퓨트 시스템은 "상태를 공유하는 기계"가 아니라 "로그에서 재계산하는
> 기계"다.** 아크 로그가 페이지 테이블이고, 페이지 폴트 핸들러는 *재계산*이며, KV 스냅샷은
> 교환 형식이 아니라 **기질별 캐시(스왑 백킹 스토어)** 다.

## 1. 매핑 (아크 → 컴퓨트 추상)

| OS 추상 | 우리 대응물 | 근거·주의 |
|---|---|---|
| **프로세스** | **아크** (PID 아님 — 봉인된 핸들) | 아크는 기기·모델보다 오래 산다. Quine의 PID 매핑은 프로세스가 곧 정체성이라 우리와 다름 |
| **주소공간** | 아크의 `tip_seq`로 색인된 **실행 프레임의 내용주소화 DAG** + 도구 서술자 | 연속 바이트가 아니라 **명명된 상태의 집합** |
| **페이지 테이블 루트** | 아크의 **compaction root**(인과 tip 해시) | 우리 `tip_hash`가 이미 이 역할 |
| **페이지** | 재료화된 어텐션 상태(HBM 상주분) | **KV 스냅샷 자체가 아님** — §2 |
| **스왑/백킹 스토어** | **KV 스냅샷** (Prefill-Once-Fan-Out / Mooncake류 저장소) | 기질 내부 최적화 |
| **페이지 폴트** | 아크 재개 시 필요한 프리픽스가 상주하지 않음 = **prefix cache miss** | |
| **폴트 핸들러** | **로그에서 재계산** — 단, 궤적 해시 검증을 통과한 경우에만 | = compaction validation |
| **MMU / 보호** | **게이트 술어 평가기**(Proof-or-Stop형): 신선하고 소스-상태에 묶인 증거만 승인 | 링/유저-커널이 아님 |
| **쓰기 권한** | **Write = append-only**, 무효화는 `supersede` | 이미 구현됨 (INV-7) |
| **권한 도메인** | **delegation-depth narrowing** (위임할수록 스코프 축소) | ACAP 계열 |
| **시스템 콜** | `claim-with-lease` / `progress` / `supersede` / `handoff` / `close` | 트랩이 아니라 **로그에 대한 원자적 append**이며, 그 효과는 *가시성 변경* |
| **클록** | **`tip_seq` = 논리 시계.** 실시간은 오직 lease 만료에만 | 우리가 이미 이렇게 하고 있음 |
| **스케줄러** | 요청이 아니라 **세션(아크) 단위**, 시간 양자가 아니라 **폴트에서 선점** | SMetric/Justitia 계열 |
| **페이저/스와퍼** | **워치독** — 죽이는 자가 아니라 **압축해서 내보내는 자** | 고아 아크를 팩으로 압축 후 회수 |
| **OOM reaper** | 워치독의 thrash 플래그 | 이미 구현됨 |

## 2. 결정적 교정 — KV 스냅샷은 페이지가 아니다 (council)

내 초안은 "KV 스냅샷 = 상주 페이지"였다. **틀렸다.**
- KV 스냅샷은 **모델 가중치 해시·토크나이저·양자화에 잠겨 있다.** 다른 모델에 건네는 순간
  캐시 불변식이 깨지고, 재-프리필이 강제되거나 **조용한 환각**이 된다.
- 우리 요구사항은 **이종성**(claude/codex/로컬 qwen이 서로 이어받음)이다. 따라서
  **KV 스냅샷은 교환 형식이 될 수 없다.**
- **유일하게 타당한 이종 인수인계는 "원시 이벤트 로그를 넘기고, 인수자가 자기 KV를 스스로
  재계산하는 것"이다.**

**함의(중요):** 우리 사회가 **파일 기반·로그 기반**이라 "원시적"으로 보였던 것이, 이종성 아래에서는
**정확히 옳은 설계**였다. KV 스냅샷 공유는 *동일 기질 내부의 최적화*로만 도입한다 —
계층 하나 아래, 옵션으로. 이것이 소버린티 테제의 컴퓨트 층 표현이다:
**우리는 상태를 신뢰하지 않고 로그를 신뢰한다.**

## 3. 스케줄링 목적함수

- 처리량(throughput)이 아니라 **MTTR(재개까지 시간)과 아크 완주율**이 1차 지표다 — 사회의 주장이
  continuity/availability이므로 목적함수도 거기 맞춰야 한다(굿하트 방지).
- 선점은 **시간 양자가 아니라 폴트에서**: 아크가 재계산을 기다리는 동안 GPU를 놀리지 않는다.
- 2단 스케줄러: **입장 제어**(위임 깊이·증거 등급으로 거른다) + **배치**(어느 기질에 태울지).
- 반-thrash: `supersede`만 반복하고 `tip_seq`가 전진하지 않는 아크는 벌점 — 우리 워치독의
  `reclaim_thrash`와 같은 정신.

> ⚠ **검증 안 된 부분(정직 표기):** council 답변은 특정 학회·수치(예: "FIFO 대비 40% 개선",
> 특정 개최지)를 제시했으나 **1차 출처로 확인하지 못했다.** 위 목적함수는 우리 지표 논리로
> 재구성한 것이며, 인용 수치는 채택하지 않는다.

## 4. 이 매핑이 오도하는 지점 (OS 유비의 한계)

1. **결정성 부재.** OS 페이지는 재계산하면 같은 값이지만, 아크 재계산은 **모델 샘플링 때문에 같은
   값이 아니다.** ⟹ 폴트 핸들러의 정합성 기준은 "비트 동일"이 아니라 **오라클 통과**여야 한다.
   (우리 G2가 이미 행동 기준으로 판정하는 이유.)
2. **컨텍스트 스위치가 싸지 않다.** 프리필 비용이 실재하므로 "가볍게 왔다갔다"를 전제하는
   스케줄링은 무너진다 — 그래서 세션 단위 스케줄링이다.
3. **idempotence 없음.** 도구 호출은 부작용을 남긴다. 페이지 재적재와 달리 **재실행이 안전하지
   않다.** ⟹ 재계산은 *읽기 경로*에만 자유롭게 허용하고, 쓰기·외부 작용은 영수증으로 1회성 보장.
4. **주소 변환이 없다.** "가상 주소 → 물리 주소" 같은 전단사가 없다. 있는 것은 **검색과 관련성**
   뿐이며, 이걸 MMU라 부르면 정확도를 과대평가하게 된다.

## 4b. 적대 council — OS 프레이밍이 아무것도 사주지 않을 수 있다 (7건, high 4)

가장 아픈 지적부터. **이것이 이 문서 전체의 게이트가 된다.**

1. **"queue + files 대비 무엇을 사는가" (high).** OS 형태의 층이 무권한 읽기·유출 시도·낡은 권한
   커밋·교차 캐시 관찰을 **최소 큐+파일 기준선보다 줄이지 못한다면 사는 것이 없다** — 오히려
   특권 코드와 저장 메타데이터만 늘린다. ⟹ **§5의 C1~C3는 각각 "이것이 없으면 불가능한 능력"을
   먼저 대야 한다.** (우리 자신의 게이트 규칙과 동일: *현 shape로 불가능한 능력 1개 증명 전엔
   신인프라 금지*.)
2. **중앙 통제면 = 단일 신뢰 기반 (high).** resume pack·KV 핸들·능력·리스·영수증을 한 곳에
   모으면, 역직렬화 하나·경로 순회 하나·인가 누락 하나로 **모든 아크가 한꺼번에 노출**된다.
   큐 아이템 하나가 아니라. ⟹ 통제면을 만든다면 **최소권한·분할**이 전제.
3. **append-only 원장이 2차 데이터 저장소가 된다 (high).** 프롬프트·도구 인자·출력·URL·파일명·
   스택트레이스가 **영구 보존**된다. 사용자 표시 출력만 마스킹하면 로그·영수증·트레이스·크래시
   덤프에서 복구 가능하고, **append-only는 삭제·철회 요구와 충돌**한다. ⟹ 우리 프라이버시 경계는
   기록 계층에서 재검토 필요(현재 아크에 원문을 넣지 않는 규칙은 있으나 강제되지 않음).
4. **sleep-time GC/prefetch가 권한을 넓힌다 (high).** 배경 프리페치가 프라이버시-게이트 데이터를
   더 넓은 캐시에 물질화하고, 배경 GC가 **원 아크보다 큰 권한**으로 기록을 훑을 수 있다.
5. **공유 GPU에서 유휴는 직교하지 않는다 (med).** "유휴 시간 회수"는 개선되어도 p95 생성 지연이
   악화될 수 있다 — sleep-time compute를 공짜로 계산하면 안 된다.
6. **주소공간은 위치가 아니라 내용으로 주소화된다 (med).** 프리픽스가 조금만 달라도(시스템
   프롬프트의 user id 하나) 캐시가 무효화되어 "팩 적재 시간"은 좋아지고 **완주 시간은 나빠진다**.
7. **워치독 통제면 자체가 공격면 (med).** 진행·하트비트·리스 갱신을 아크가 공급하면 악성 아크가
   무한 상주·기아 유발·갱신 폭풍을 만들 수 있고, 임계값이 전역이면 반복 취소/재시작으로
   **프로바이더 비용을 증폭**시킬 수 있다.

## 5. 최소 착수 (게이트 이후, 순서 고정)

**C0 (지금 가능, 비용 0):** 용어 정렬 — 아크 = 프로세스, 팩 = 주소공간 서술자, 워치독 = 페이저,
`tip_seq` = 논리 클록. 코드/문서에 이 이름을 쓴다. 개념 부채를 없애는 것이 첫 이득.

**C1 — 폴트 핸들러 정식화:** `resume`을 "팩 읽기"에서 **"필요한 것을 재계산해 상주시키는 폴트
핸들러"** 로 승격. 즉 팩에 *무엇이 재계산 가능한지*(레포 커밋, 오라클, 도구)를 명시하고,
재계산 결과가 오라클을 통과해야 상주로 인정.

**C2 — 세션 단위 스케줄러:** 여러 아크가 동시에 살아있을 때 어느 것을 어느 기질에 태울지 결정.
1차 지표 MTTR·완주율. (지금은 워치독이 FIFO에 가깝다.)

**C3 (옵션, 동일 기질 한정):** KV 스냅샷/프리픽스 캐시 재사용을 **성능 최적화로만** 도입.
이종 경로에는 절대 노출하지 않는다.

**게이트 순서 불변:** N1(G5: 사회 > solo+원장)이 먼저다. 사회가 정당화되지 않으면 C1~C3는 짓지 않는다.
사전등록 동결: `docs/AIOS_G5_SOCIETY_PREREG_2026-08-03.md`.

### 5b. 각 단계의 "이것 없이는 불가능한 능력" (적대 council §4b.1의 요구)

착수 전 각 단계는 아래 칸을 채워야 하며, **빈 칸이면 짓지 않는다.**

| 단계 | queue+files로 불가능한 능력 | 상태 |
|---|---|---|
| C0 용어 정렬 | (없음 — 비용 0의 개념정리이므로 게이트 면제) | 즉시 |
| C1 폴트 핸들러 | *결과를 신뢰 없이 재사용* — 캐시 히트를 오라클 동치로 정당화 | **미충족**: 오라클 동치 정의가 아직 없음(0→10 문서의 6단 연구 문제) |
| C2 세션 스케줄러 | 다중 아크 동시 상황에서 **기아 방지** — 단일 큐로는 세션 단위 공정성을 표현 불가 | **미충족**: 동시 아크가 아직 1개 |
| C3 KV 재사용 | (동일 기질 한정 성능 최적화 — 능력 아님) | **면제 불가**: 능력이 아니므로 N1·C1 이후로 후순위 |

⟹ **현재 착수 가능한 것은 C0(이름 교체)뿐이며, 나머지는 게이트 미충족이다.** 이것이
"queue+files 대비 무엇을 사는가"에 대한 우리 답이다: **아직은 아무것도.** 정직하게 그렇게 적는다.
