# 배포 계획 — Orca처럼 패키징된 서비스로 (2026-08-03)

founder: *"Orca 같은 패키징된 서비스로 만들고 싶다. Deployment."*
**이 문서는 배포 준비상태 실측 + 단계별 계획 + 차단 사유다.**

## 0. 우리는 Orca와 같은 물건이 아니다 — 이것이 패키징을 결정한다

Orca는 **작업공간/IDE 앱**이다(워크트리·터미널·내장 브라우저·에디터 런타임). 사용자에게 도구를
바꾸라고 요구한다. 우리 제품은 그게 아니다.

> **우리 제품 한 문장: "에이전트가 죽어도 당신의 작업은 죽지 않는다."**
> 형태는 앱이 아니라 **사이드카** — 사용자가 이미 쓰는 에이전트(Claude Code / Codex / Cursor /
> 로컬 LLM) 옆에 붙는다. 도구를 바꾸라고 하지 않는 것이 유일한 현실적 진입로다.

⟹ 1차 배포 채널은 **MCP 서버**다. 2026 표준 관행이 정확히 그것이고(우리는 이미 MCP 서버 +
16 툴 + Claude 플러그인 보유), 사이드카는 클라이언트 안에서 소비되기 때문이다.

## 1. 준비상태 실측 (2026-08-03, 추정 아님)

| 항목 | 상태 | 증거 |
|---|---|---|
| PyPI 이름 `aios-os` | **비어 있음(선점 가능)** | pypi.org API 404 (`aios`, `akashic`은 이미 점유) |
| 의존성 | **0개 (stdlib only)** | `dependencies = []` → uvx/pip 설치가 깨질 여지 최소 |
| 설치 경로 | `pip install` · `uvx --from aios-os aios-mcp` · `install.sh` (curl \| sh) | 3채널 모두 존재 |
| 엔트리포인트 | `aios`, `aios-mcp` | 클린 venv에 실제 생성 확인 |
| Claude 플러그인 | 존재 (`plugin/aios/`: `.mcp.json`, hooks, plugin.json) | |
| 클린 venv 설치 | **성공, 12/12 핵심 모듈 import OK** | `/tmp/aios_pkgtest` |
| 패키지에서 사회 CLI 동작 | **레포 없이 open/claim/pack/verify 전부 성공** | 위 venv에서 실행 |

### 1b. 실측이 잡아낸 치명적 결함 2건 (둘 다 오늘 수정)

1. **출하 메타데이터가 우리가 반증한 주장을 광고하고 있었다.**
   기존 description: *"keeps a behavioral-memory ledger … so your agents carry forward what
   worked"* — 이것은 X-채널 null이 죽인 바로 그 문장이다(`C_overall = 0.000`).
   ⟹ 재스코프 정체성으로 교체 + **금지 문구 회귀 테스트** 추가
   (`tests/test_packaging_completeness.py::test_description_does_not_advertise_a_falsified_claim`).
2. **출하 코드가 import하는 모듈 14개가 패키지에 없었다.**
   `aios_turn_loop`(커널 척추), **`aios_egress_gate`·`aios_authority`(소버린티 강제)**,
   `aios_freshness`, `aios_self_audit`, `aios_stakes` 등. 즉 **휠이 강제할 수 없는 소버린티를
   광고**하고 있었고, `pip install` 후 핵심 경로가 ImportError로 죽었다. 사회 모듈 3종도 미등재.
   ⟹ 전부 등재 + **import 그래프 정적 검사 회귀 테스트**(10 tests green).

> 교훈(기록): **"패키징돼 있다"와 "설치하면 동작한다"는 다른 명제다.** 앞으로 릴리스 전
> 클린 venv 설치 + 스모크가 의무.

## 3. 단계별 배포 (각 단계는 앞 단계의 게이트를 통과해야 함)

### D0 — 지금 가능: 로컬 단일 사용자 사이드카 (v0.3)
- **무엇:** `pip install aios-os` / `uvx --from aios-os aios-mcp` / Claude 플러그인.
  네트워크 없음, 원격 없음, 계정 없음. 데이터는 사용자 기계에만.
- **정직한 기능 목록(오늘 참인 것만):** 작업 아크 원장(변조증거) · 컨텍스트 죽음 후 신선도 게이트
  재개 · 죽은 세션의 고아 작업을 살아있는 기질로 회수 · 외부 오라클로 검증된 인수인계 ·
  커널 강제 샌드박스(무네트워크 기본, 프라이버시 디렉터리 불가시).
- **남은 일:** README/문구를 재스코프 정체성으로 통일(B2 포함), 릴리스 스모크 절차 문서화,
  버전 0.3.0 태깅. *코드 작업은 사실상 끝났다 — 남은 것은 문구와 릴리스 위생.*

### D1 — 다기기 (B1 해결 후)
아크 동기. 게이트: 강제 스크럽 + 삭제 가능 층/불변 층 분리가 **테스트로 증명**될 것.
참고 구조: Orca의 `devices[].{token,scope}` + `relayBinding.ownerIdentityKey`(재발명 금지).

### D2 — 사회를 *주장*으로 판매 (G5 통과 후)
G5가 C ≤ B로 나오면 이 단계는 **영구 취소**되고, 우리는 D0을 "단일 에이전트의 영속 기억"으로
계속 판다(코드는 낭비되지 않는다).

### D3 — 검증 엔드포인트 = 우리 정체성에 맞는 유일한 "호스팅 서비스"
`deploy/akashic-worker/`(작성됨, 미배포): Merkle root / 포함 증명 / 독립 검증.
**데이터가 아니라 증명을 서빙한다** — 소버린티를 깨지 않는 유일한 서버 형태.
게이트: N3(위조 attestation 검출).
