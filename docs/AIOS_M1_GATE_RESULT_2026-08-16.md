# M1 정직성 게이트 결과 — 돌리지 않는다 (2026-08-16)

사전등록(`docs/AIOS_M1_MEMORY_EDGE_PREREG_2026-08-14.md` §3)은 풀런 전에 하나를 요구했다:

> 회수된 pack이 **실패 서명만으로 유도 불가능한** 정보를 담고 있는가?
> 오프라인 테이블이 pack 내용의 80% 이상을 재현하면 풀런하지 않는다.

측정했다. **결과: 실행하지 않는다.** 다만 이유가 memory에 대한 것이 아니다.

## 1. 측정 — 실패 서명의 정보량

모집단: G5+G6의 실제 시도 292건 중 **실패 164건**
(`experiments/phase5g/g5_results.jsonl`, `experiments/phase5h/g6_results.jsonl`).

```
fail_reason 기준 서명:  2가지        entropy 0.811 bits
                        전부 "oracle_failed", 차이는 rc=1(123) vs rc=2(41)
```

기록된 **모든** 필드의 판별력을 재봤다:

| 필드 | 값 개수 | 엔트로피 | 무엇인가 |
|---|---:|---:|---|
| `fail_reason` | 1 | **0.000** | 전부 `oracle_failed` |
| `infra_error` | 1 | 0.000 | 전부 `None` |
| `tests_tampered` | 1 | 0.000 | 전부 `[]` |
| `passed` | 1 | 0.000 | 전부 `False` (실패만 보므로 당연) |
| `oracle` | 32 | 4.067 | 그러나 키가 `{ok, passed, rc}`뿐 |
| `task_id` | 75 | 6.091 | **어느 과제인가** — 진단 아님 |
| `arm` | 4 | 1.797 | **어느 조건인가** — 진단 아님 |
| `seq`·`wall_s`·`ts_finished` | 多 | 5.7~7.4 | 실행 장부 |

> **비트를 가진 필드는 전부 실험 장부다.** 어느 테스트가, 어느 단언에서, 어느 파일에서
> 깨졌는지 — 진단에 필요한 것은 **하나도 기록되지 않았다.** 하네스가 모든 오라클 실패를
> `oracle_failed` + rc + 통과 개수로 뭉갰다.

## 2. 그래서 게이트는 왜 실패인가

두 단계다.

**(a) 회수 키가 1비트 이하다.** 실패 서명으로 인덱싱한 오프라인 테이블은 최대 2행이고,
같은 키로 하는 런타임 회수는 **원리상** 그 테이블이 이미 결정한 것 이상을 낼 수 없다.
재현율은 사실상 1.0이고, 게이트 문턱(0.8)을 넘는다.

**(b) 더 나쁜 쪽 — arm D가 baseline이 아니라 거의 오라클이 된다.** `task_id`가 6.09비트를
가진다. 실패 기록을 task_id로 인덱싱하면 오프라인 테이블은 **과제별 처방을 사실상 암기**한다.
그러면 `C vs D`는 자연이 아니라 **계측이 C에게 불리하게 조작한 대비**가 된다.

⟹ 지금 돌리면 나오는 null은 **memory에 대해 아무 말도 하지 않는다.** 그건 우리가
"어느 과제인지"는 기록하고 "무엇이 깨졌는지"는 기록하지 않았다는 사실의 재진술이다.

## 3. 이것이 `observable-competence ceiling`의 우리 버전이다

A1이 말한 천장은 *"결정에 필요한 것이 전부 context key에 있으면 lookup이 이긴다"*였다.
우리 데이터에서는 그것이 **자명하게 성립한다** — key가 task 정체성이고 실패 내용은
비어 있으니, lookup이 이기는 게 당연하다.

**천장이 시험된 게 아니라 빈약한 키로 자동 충족됐다.** 그 구별이 이 게이트의 전부다.

## 4. 실행 조건 (다음 시도의 좌표)

M1은 하네스가 **진단이 담긴 실패 서명**을 기록한 뒤에 돌린다. 최소:

```
failing_test_id      어느 테스트
assertion            무엇이 어긋났는가 (정규화된 단언 텍스트)
file:line            어디서
traceback_head       상위 프레임 3개
exit_class           rc가 아니라 분류 (assert / import / timeout / crash)
```

**검증 가능한 통과 조건**: 새 계측으로 같은 모집단을 재기록했을 때
서명 엔트로피가 **≥ 3.0 bits**이고, 그중 **task_id로 설명되지 않는 잔차**가
**≥ 1.5 bits**일 것. 잔차가 없으면 여전히 lookup이 이기고, 그때는 M1이 아니라
**테이블을 강제하는 것**이 맞다.

## 5. 정직한 한계

- 이 게이트는 **G5/G6 모집단**에 대한 것이다. 다른 실패 분포에서는 다를 수 있다.
- 서명이 빈약한 것이 **하네스의 성질**이지 실패의 성질이라고 주장하지 않는다.
  실제로 그 과제들이 한 가지 이유로만 깨졌을 수도 있다 — 그건 새 계측이 답한다.
- 재현율 0.8 문턱은 사전등록에 적힌 값을 그대로 썼고, 결과를 보고 바꾸지 않았다.
