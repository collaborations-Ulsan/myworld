# 사전등록 — M2: 기억은 정보가 아니라 계산인가 (2026-08-16)

**상태: 사전등록. 데이터를 보기 전에 동결한다.** 개정은 append-only Errata로만.

M1(`docs/AIOS_M1_MEMORY_EDGE_PREREG_2026-08-14.md`)은 NO-GO로 남는다. 이것은 그 실험의
완화판이 **아니라 다른 추정량**이다 — 못 이긴 주장을 옆으로 옮긴 게 아니라는 증명 책임은
§5가 진다.

## 0. 왜 이 실험인가 — 두 개의 관측

### (a) 내 식별가능성 걱정은 틀렸다 (실측)

`docs/AIOS_RESIDUAL_DECISION_VALUE_2026-08-16.md` §5 Gate 1은 `Var(S∣K)>0`와 행동 overlap을
요구한다. 나는 내 도메인에 그게 없다고 적었다. **재봤더니 있다.**

```
attempts 292 · task_id 114개 · task당 정확히 2회 또는 4회 (arm별 1회씩)
같은 task_id 안에서 결과가 갈리는 경우: 26 / 114
```

**G5/G6는 이미 matched paired 설계였다** — 같은 과제를 arm만 바꿔 돌렸다.
패널이 "Gate 2: 가장 싼 확정 실험"으로 처방한 twin/matched 구조가 이미 데이터에 있다.

> **여기서 하나 분리해야 한다.** `task_id` 반복은 **예측자로 쓰면 누출**이고
> **블록 인자로 쓰면 식별**이다. M1 Errata E2("D를 task_id로 인덱싱하지 마라")와
> 이 발견은 모순이 아니다 — 같은 반복의 서로 다른 용법이다.

### (b) 그 짝지음 위의 사후 관측 — **주 결과가 아니다**

| 대비 | 불일치쌍 | 정확 McNemar p |
|---|---|---|
| `solo_ledger` vs `solo_norecord` (n=114쌍) | 16 / 6 | **0.0525** |
| `society` vs `solo_ledger` (n=32쌍) | 3 / 5 | 0.727 |
| `society` vs `society_rev` (n=32쌍) | 4 / 2 | 0.688 |

**이것은 사후분석이다.** G5의 사전등록 주 대비는 society vs solo였고 −6.25pp로 kill rule이
발동했다. 위 표의 첫 줄은 내가 오늘 처음 계산한 **부차 대비**이며, p=0.0525는 문턱을
넘지 못했고 다중비교 보정도 안 했다. **가설 생성 이상으로 쓰지 않는다.**
쓸 수 있는 유일한 결론은 방향이 이 실험의 가설과 어긋나지 않는다는 것뿐이다.

## 1. 바뀐 주장

지금까지 물려받은 주장: *"런타임 활성화가 offline-optimal을 이긴다."*
A1/MCF-0에서 졌고, M1에서는 계측 때문에 물을 수조차 없었다.

새 주장은 더 좁고 더 반증 가능하다:

> **기억의 값은 에이전트에게 더 많이 알려줄 때가 아니라, 덜 계산하게 만들 때 있다.**

`S = f(K)`면 Shannon 정보는 0이다. 그러나 `f`가 비싼 검색·추론이면 **제한된 예산의
정책에게는** 값이 있다. 정보적 충분성과 계산적 충분성은 다른 것이고,
M1은 앞의 것만 잴 수 있었다.

## 2. 팔 (3개) — 강한 대조군이 핵심

```
A  fresh recomputation      지속 상태 없음. 매번 다시 계산한다.
B  conventional cache       최선의 재래식 캐시·materialization. 우리 것이 아님.
                            (내용주소 캐시 + 프롬프트 캐시 + 정적 인덱스)
C  memoryOS persistent      draft/accept 생명주기·provenance를 갖춘 우리 기질
```

**B가 이 설계의 전부다.** B 없이 C가 A를 이기면 우리가 발견한 것은 memoryOS의 고유 가치가
아니라 **캐싱 일반의 가치**이고, 그건 이미 세상이 안다.

## 3. 게이트 순서 (순서를 바꾸면 결과는 VOID)

**Gate 0 — 추정량 사전 고정.** 아래는 데이터 수집 전에 확정한다.

```
효용 U          외부 오라클이 판정한 verified task success (최적화기 접근 불가)
결정 시점       각 시도 시작 시점
합법적 K        그 시점에 실제 배치에서 관측 가능한 것만. task_id 제외.
블록            task (짝지음). arm은 task 내에서 무작위 순서.
일반화 단위     새 task (task 단위 split. train·test에 같은 task 금지)
δ_NI            비열등 마진 = 5pp (절대)
δ_min           비용 우위 최소 실용 효과 = 25% 감소
```

**Gate 1 — 능력 비열등 (하드 게이트).** 비용을 보기 전에 통과해야 한다.

```
C가 A에 대해 verified success rate에서 비열등:
   (C − A)의 단측 95% 하한 > −δ_NI
```

⟹ **통과 못 하면 비용 비교를 하지 않는다.** 싸게 못 푸는 것은 싼 게 아니다.
이 게이트가 "능력 주장을 못 이겨서 비용으로 도망쳤다"를 구조적으로 막는다.

**Gate 2 — 비용.** Gate 1 통과 팔에 한해:

```
tokens · wall time · model calls · provider calls · joules proxy
주 지표:  verified task utility retained / fresh model compute
```

**Gate 3 — 소버린티 (provider 교체).** 전 팔의 모델을 **동결된 대체 모델**로 갈아끼우고
Gate 1·2를 재측정한다. 이것이 provider-death 내성을 능력 주장이 아니라 **측정**으로 만든다.

## 4. Kill rule

```
Gate 1 실패                          ⟹ 폐기. 비용 비교 안 함.
C ≤ B (주 지표)                       ⟹ 우리가 발견한 것은 캐싱이다. memoryOS 고유가치 주장 철회.
(C−B)의 단측 95% 하한이 δ_min 미만     ⟹ 기본값 OFF · 성능 주장 없음.
모델 교체 후 C의 우위 소멸             ⟹ 우위는 특정 provider와의 상호작용. 소버린티 주장 철회.
```

`Gate 1`의 판정은 **등가성/비열등 검정 형식**으로 한다. *"차이를 발견하지 못했다"*는
비열등의 증거가 아니다 — 신뢰구간 상한이 마진 안에 들어와야 한다.

## 5. 이것이 도망이 아님을 무엇으로 보이는가

재프레임은 못 이긴 주장을 버리고 이길 만한 주장으로 옮기는 방식으로 남용될 수 있다.
그것과 구별되는 조건 셋을 **미리** 건다:

1. **능력 주장을 취소하지 않는다.** Gate 1이 하드 게이트로 남는다. C가 A보다 유의하게
   나쁘면 비용이 아무리 좋아도 실패다.
2. **강한 대조군을 세운다.** B는 우리 것이 아니고, 우리가 이기기 쉽게 약화시키지 않는다.
   B의 구현은 이 문서 동결 후 **C와 무관한 사람/기질**이 최선을 다해 만든다.
3. **결과를 분리 보고한다.** M1/A1의 능력 결과는 그대로 인용되고, 이 실험의 결과가
   그것을 소급해 해석하지 않는다. 별 실험, 별 추정량.

세 조건 중 하나라도 깨지면 이건 재프레임이 아니라 후퇴다.
