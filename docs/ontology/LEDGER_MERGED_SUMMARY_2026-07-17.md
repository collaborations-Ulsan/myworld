# Unified Knowledge Ledger — merge summary (2026-07-17)

**What this is**: the output of OntologyOS v0's merge/normalize/query organ
(`experiments/ontology/`) running against the 4 wave-1 domain ledger files
named in `FRONTIER_KNOWLEDGE_LEDGER_2026-07-17.md` §1. This is both the QA
gate for wave-1 and the first real OntologyOS organ — it turns 4 structurally
divergent JSON files into one deduped, validated, queryable ledger:
`docs/ontology/ledger/_merged.json`.

Generated by: `python3 experiments/ontology/run_merge.py` (deterministic,
stdlib-only, read-only against the 4 sources).

## 0. The QA finding that motivated this: the 4 files do NOT share a shape

Inspected directly (not assumed) before writing a line of normalizer code:

| file | entities shape | relation shape |
|---|---|---|
| `docs/ontology/oaklab_agi_ontology.json` | flat list, fields nested under `attributes` | `{type, from, to, source}` |
| `docs/ontology/ledger/agi.json` | **entities NESTED as a dict-by-type** (`{"Domain": [...], "Person": [...], ...}` — no per-entity `type` key) | `{type, from, to, source}` |
| `docs/ontology/ledger/physical_ai.json` | flat list, fields nested under `attrs` | `{src, rel, dst, source}` |
| `docs/ontology/ledger/medical.json` | flat list, fields **directly on the entity** (no nested container) | `{from, rel, to, source}` |

`experiments/ontology/normalize.py` auto-detects and adapts to all 4 shapes
(`normalize_oaklab`, `normalize_agi`, `normalize_physical_ai`,
`normalize_medical`) into one canonical schema:
`entity = {id, type, name, attrs, source, domain}`,
`relation = {src_id, rel, dst_id, source, domain}`.

## 4. Top contradictions across ALL domains

The full 36-edge list is queryable via
`python3 experiments/ontology/query.py contradictions`. Highlights per domain
(both endpoints named, with `source`):

**D1 — AGI / foundation capability** (14 contradicts edges — the domain with
the most live frontier disagreement):
- *Reward Hypothesis vs multi-objective critique*: "Reward maximization is by
  itself sufficient to underpin all intelligence" **vs** "A single scalar
  reward is NOT sufficient; capturing intelligence needs multi-objective /
  vector-valued rewards" (direct rebuttal, "Three Dogmas of RL" vs "Reward is
  Enough").
- *GEPA overfits vs GEPA outperforms* (the CORE frontier disagreement per
  agi.json's own annotation): RELAI-VCL shows GEPA transfers **below**
  baseline on continual eval (76.4% RELAI vs 66.0% GEPA lifelong) **vs** the
  GEPA paper's claim that reflective Pareto prompt evolution outperforms RL.
  A second, independent contradiction pair repeats the same clash: GEPA
  degrading GSM8K 23.81%→13.50% on a defective seed (VISTA recovers to
  87.57%) vs the same "GEPA outperforms RL" claim.
- *Memory helps vs memory hurts*: "Bolt-on memory scaffolds UNIVERSALLY hurt
  long-horizon performance across all 10 tested models (23,392 episodes)"
  **vs** "Memory helps IF the agent learns to USE it — a 9B model with
  learned memory-use challenges a 397B model."
- *LLMs as AGI path*: "LLMs are a dead end for AGI... Experiential learners
  will supersede them" **vs** "pretrained LLMs can serve as a convenient
  prior/intermediary... non-renewable does not mean dead-end" (the "fossil
  fuels" rebuttal).
- *Self-improvement source of gains*: "self-generated skills may DEGRADE
  [performance]; self-feedback alone induces recursive drift" **vs** two
  independent RSI-positive claims (Darwin Gödel Machine's open-ended archive
  evolution; AIDE²'s "first net-positive RSI" claim).

**D3 — Physical / Embodied AI** (10 contradicts edges — mostly paper-vs-paper
methodology disputes):
- "Much Ado About Noising: Dispelling the Myths of Generative Robotic
  Control" **vs** "Diffusion Policy: Visuomotor Policy Learning via Action
  Diffusion" — disputes that Diffusion Policy's edge is multimodality,
  attributes it to iterative supervised compute instead.
- "VLA-0: Building SOTA VLAs with Zero Modification (actions as text)" **vs**
  "FAST: Efficient Action Tokenization for VLA Models (pi0-FAST)" — competing
  action-representation claims.
- "V-JEPA 2: ... Zero-Shot Robot Planning" **vs** "Genie: Generative
  Interactive Environments" — competing world-model-for-control approaches.

**D2 — Medical / Biomedical AI** (11 contradicts edges — mostly
"foundation-model-beats-baseline" claims disputed by a narrower/harder
result):
- "Multi-agent collaboration does NOT consistently beat strong single LLMs
  or specialized classical ML" **vs** "MAI-DxO reaches 85.5% diagnostic
  accuracy on SDBench vs ~20% for 21 generalist physicians."
- "Single-cell foundation/DL models fail to beat simple linear/additive
  baselines on perturbation prediction" **vs** two independent positive
  claims (STATE's >50% improvement on perturbation discrimination; C2S-Scale
  27B's wet-lab-validated drug-combo prediction) — the same skeptical claim
  contradicts two different positive results.
- "Best medical MLLM scores ~65% vs 96% human on trivial perceptual checks"
  **vs** "Pillar-0 (native-volumetric radiology FM) beats
  MedGemma/MedImageInsight/Lingshu/Merlin by 7.8–15.8 AUROC."

## 6. Dropped dangling edges: 1 — and exactly why

```
model:v_jepa_2_v_jepa_2_ac  --[evaluated_on]-->  bench:droid
source: "V-JEPA 2-AC zero-shot Franka pick-place from 62h DROID video"
```

`physical_ai.json` has a relation `{"src": "model:vjepa2", "rel":
"evaluated_on", "dst": "bench:droid", ...}` but **`bench:droid` is not an
entity anywhere in `physical_ai.json`'s own entity list** — its 8 Benchmark
entities are `libero, robocasa, maniskill3, roboarena, calvin, simplerenv,
robomimic, ht_bench`; DROID (the dataset V-JEPA 2-AC was evaluated against)
was never entered as a Benchmark/Dataset node. This is a genuine data-quality
gap in the source file itself, not an artifact of normalization or merge —
confirmed by inspecting the raw file directly. It is dropped (not silently
kept, not fabricated into a fake entity) and logged in `_merged.json`'s
`dropped_danglers` with the reason `dangling_dst`.
