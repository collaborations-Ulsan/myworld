# 생태계 provisioning — 내가 못 만든다는 제약을 뺀 설계

founder 진단: *"네가 지어야 한다고 생각하니까 오히려 과대축소해버리는 경향이 있네.
너는 Ideation만 담당한다고 생각했을 때 어디에 어떤 언어를 어떻게 붙이고, 라이브러리를
사용하고, … provisioning"*

정확한 진단이다. 내 앞선 답들("Lean 6파일은 미사용이니 보류", "WASM은 플러그인 0개니 보류",
"최소동작 하나만")은 전부 **내 유지보수 능력을 상한으로 놓고 역산한 것**이다. 그건 생태계
설계가 아니라 1인 프로젝트 스코핑이다. 아래는 **그 제약을 뺀** 설계다. 구현 배분은 별개 문제로
§8에 분리해 둔다.

> **판단 규칙 (이 문서 전체를 관통)**: 언어·런타임은 **보증(guarantee)** 단위로 배치한다.
> 속도로 고르지 않고, 유행으로 고르지 않고, "내가 쓸 줄 아니까"로 고르지 않는다.
> 그리고 **표준이 이미 있으면 우리 포맷을 만들지 않는다** — §1이 그 첫 적용이다.

---

## 0. 층 배치 요약

| 층 | 제공해야 할 보증 | 언어/런타임 | 왜 그것 |
|---|---|---|---|
| **P0 계약** | 언어 무관 · 해시가 구현 간 일치 | 없음(스펙) | JSON/CBOR + 정준화 |
| **P1 강제** | 우회 불가 · 무결함 · 남의 기기에 배포 | **Rust** | 크래시·우회가 치명적인 유일한 층 |
| **P2 확장** | 참여자가 **자기 언어로** 기여 | **WASM Component Model** | WIT가 다언어 ABI |
| **P3 원장** | 추가전용 · 질의 가능 · 투명성 | SQLite / Parquet / 투명성 로그 | 어디에나 있고 단일 파일 |
| **P4 증명** | 설득 불가능한 판정 | **Lean 4** · **TLA+** | 오라클은 논쟁 대상이 아니어야 |
| **P5 표면** | 에이전트·사람이 닿는 곳 | Python(MCP) · TypeScript | 생태계가 이미 거기 있음 |
| **P6 배급** | 우리에게 묻지 않고 노드를 세움 | 다중 채널 | provisioning이 곧 생태계 |

## 1. P0 계약 — 우리 포맷을 만들지 말 것 (오늘 갱신됨)

**오늘 확인(2026-08-10 검색)**: **SCITT가 RFC 9943으로 발행됐다.** transparency service가
정책을 검사한 뒤 signed statement를 원장에 등록하고 **receipt를 발급**하는 구조다.
API 규격 SCRAPI는 IETF 드래프트로 진행 중.

> **⚠️ 2026-08-10 재교정 — 위 문단의 결론("재발명이니 버린다")이 틀렸다.**
> founder: *"재발명이 아니라, 기존 인프라를 잘 사용해서 우리쪽으로 흡수시킨 후 발전시키는
> 것도 더 큰 발견."*
>
> **내 방법론에 칸이 하나 없었다.** 나는 선행연구 환원을 이분법으로 돌려왔다 —
> 환원되면 재명명(버림), 안 되면 novel. 실제 결과는 셋이다:
>
> | 환원 결과 | 올바른 조치 |
> |---|---|
> | (a) 완전 환원, 잔여 없음 | 재명명 — 버린다 |
> | (b) 환원 불가 | novel — 증인이 필요 |
> | **(c) 부분 환원 + 잔여 불변량** | **기반은 흡수, 잔여는 기여** ← 나에게 이 칸이 없었다 |
>
> 그리고 (c)가 가장 흔하고 가장 값지다. 표준을 소비하면 소비자가 되지만,
> **표준을 흡수하고 잔여를 되돌려주면 그 표준의 공동저자가 된다.**
> 생태계 포지션으로서 이건 자체 포맷 발행보다도, 그냥 갖다 쓰는 것보다도 강하다.
>
> 게다가 **수렴 자체가 증거다.** 내가 몇 시간 만에 독립적으로 유도한 영수증 구조가 IETF
> 워킹그룹이 수년에 걸쳐 만든 것과 같은 모양이면, 그건 낭비의 증거가 아니라 **그 모양이
> 문제에 의해 강제된다는 증인**이다. 환원은 우리 기여를 지우지 않고 **분리해낸다.**

⟹ 올바른 수는 자체 포맷도 아니고 SCITT로의 교체도 아니다. **SCITT를 흡수하고 그 위에
우리 잔여를 얹은 프로파일**을 정의하는 것이다.

### SCITT가 정하지 않는 것 = 우리 잔여 (전부 우리 측정에서 나왔다)

SCITT는 **공급망 출처**를 위해 설계됐다 — 누가 어떤 아티팩트에 대해 무엇을 말했는가.
**비결정적 생성기**를 위해 만들어진 적이 없다. 그래서 아래 절이 그쪽에 없다:

| 우리 절 | SCITT에 있나 | 어디서 왔나 |
|---|---|---|
| `sense.model_consulted == false` | ✗ | 제공형 기제 96 에피소드 **0회 사용** |
| `act.invoked_by == "host"` · `model_offered_choice == false` | ✗ | 같은 측정 |
| `verify.verifier_identity != act.operator` | ✗ | 자기채점 금지 — 3-채널 null의 교훈 |
| `verdict ⟺ outcome` 쌍조건 | ✗ | 판정이 장식이 되는 것을 막음 |
| `root_before != root_after` | 부분 (원장은 있음) | 아무것도 안 쓰고 정산 주장 금지 |
| **점등 조건에 `reverted` ≥1** | ✗ | 실행된 적 없는 되돌림 경로 = 켜진 척 |
| **`falsifier` 동봉** | ✗ | 아래 |

**가장 큰 잔여는 마지막 것이다.** SCITT의 목적은 **증언(attest)**이다 — 내가 말한 것을
믿게 만드는 것. 우리 영수증은 반대 방향을 하나 더 싣는다:

> **모든 등록된 주장이 자기를 죽일 프로그램을 함께 싣는다.**

공급망 출처에는 이런 발상이 없다(있을 이유도 없다 — 거기서 주장은 부정당하려고 등록되지
않는다). 그런데 우리 도메인에서는 **생성이 무한히 싸졌기 때문에 증언보다 반증이 희소하다.**
⟹ **`SCITT + falsifier`** = 등록된 모든 주장이 자기 반증자를 갖고 다니는 투명성 서비스.
이건 흡수가 아니라 **확장**이고, 되돌려줄 수 있는 물건이다(statement type + policy 의미론,
필요하면 SCRAPI 프로파일 드래프트).

### 이 교정은 SCITT에만 적용되지 않는다

같은 이분법으로 오늘 잔여를 함께 버린 곳이 하나 더 있다: **hop-count 프레임**.
quantum이 "compositionality gap이라는 이름이 이미 있다", universe가 "정리 D다"라고 했을 때
나는 그걸 *"우리 프레임은 novel이 아니다"*로 처리했다. (c)로 읽으면 잔여가 남는다 —
**문헌은 그 경계를 장난감 트랜스포머에서 봤고, 우리는 배치된 에이전트 시스템에서
사전등록으로 쟀다.** 그 이전은 우리 것이고, 버릴 이유가 없었다.

**순수 흡수(잔여 없음, 그대로 채택이 정답)**: RFC 8785 JCS, COSE, WASM Component Model,
Landlock/seccomp, Sigstore. 이것들은 우리가 더할 게 없고, 더하려 하면 그게 스프롤이다.

| 요소 | 채택 | 이유 |
|---|---|---|
| 정준 직렬화 | **RFC 8785 JCS** (JSON Canonicalization Scheme) | 내 `_canon()`은 손으로 만든 정렬 규칙이다. 다른 언어 구현이 **같은 해시를 낼 보장이 없다** — 생태계에서 이건 치명적 |
| 서명 | **COSE**(CBOR) / JWS | SCITT가 COSE 기반 |
| 영수증·투명성 | **SCITT (RFC 9943)** + SCRAPI | 우리 receipt 개념의 표준형 |
| 빌드 출처 | **in-toto attestation** + **SLSA** | 아래 §6에서 루프를 닫는다 |
| 서명 인프라 | **Sigstore / cosign** (keyless) | 키 관리 없이 참여 가능 = 진입장벽 제거 |
| 스키마 | JSON Schema 2020-12 (+ 필요시 protobuf/**Buf**) | Buf는 **breaking-change 탐지**가 본체 — 생태계엔 스키마보다 그게 중요 |

**우리가 유지할 것은 딱 하나**: 4-튜플의 **의미론적 제약**(model_consulted=false,
verifier≠executor, verdict⟺outcome, root 변경). 그건 SCITT가 정하지 않는, 우리 측정에서
나온 부분이다. 포맷은 빌려오고 **의미론만 우리 것**으로.

## 2. P1 강제 — 여기서 Rust는 선택이 아니다

앞서 나는 "커널이 이미 하니 Rust 불필요"라 답했다. **1인 스코프에서는 맞고, 생태계
스코프에서는 틀리다.** 차이는 셋:

1. **남의 기기에 배포된다.** `ctypes`로 libc를 부르는 Python은 우리 기기에선 되지만,
   배포판·커널 버전·Python 버전이 제각각인 참여자 기기에서 **조용히 실패**한다.
   그리고 강제 층의 조용한 실패는 정확히 우리가 금지한 실패 모드다.
2. **크래시가 곧 우회다.** 강제자가 죽으면 강제가 사라진다. GC 정지·예외 전파가 있는
   런타임을 강제 경로에 두지 않는다.
3. **단일 정적 바이너리가 진입장벽을 결정한다.** provisioning은 생태계의 실제 병목이고
   (§6), 런타임 의존성이 없는 바이너리가 그 병목을 없앤다.

| 역할 | crate |
|---|---|
| WASM 런타임 임베딩 | **wasmtime** (Bytecode Alliance) |
| LSM 강제 | **landlock** |
| syscall 필터 | **seccompiler** (AWS, Firecracker 계열) |
| 네임스페이스·자원 | **rustix**, **cgroups-rs** |
| 배포 | **cargo-dist** (설치 스크립트·서명·릴리스 아티팩트 자동) |

**대안 검토**: Go + **gVisor(runsc)**도 성립한다 — 격리가 더 강하고 운영 성숙도가 높다.
다만 WASM 임베딩과 단일 바이너리 크기에서 Rust가 낫고, wasmtime이 Rust 네이티브다.
⟹ **Rust를 1순위, gVisor를 강한 격리가 필요한 배치의 대안으로 병기.**

## 3. P2 확장 — "다양한 언어"의 진짜 답

**오늘 확인(2026-08-10 검색)**: **WASI Preview 2(0.2)가 2026년 1월 stable**, Component
Model 출시. WIT를 통해 **공유메모리 없이** Rust·Go·C++ 등 서로 다른 언어의 컴포넌트를 합성.
서버사이드 배치가 브라우저를 처음 추월(비브라우저 52%).

⟹ **우리는 다언어를 *쓰는* 게 아니라 다언어를 *받는다*.** `.wit` 인터페이스를 발행하면
참여자는 자기 언어로 구현한다:

| 언어 | 툴체인 |
|---|---|
| Rust | `cargo-component` |
| Go | TinyGo |
| Python | `componentize-py` |
| JS/TS | `jco` |
| C/C++ | `wasi-sdk` |
| Java/Kotlin | 진행 중 (2026 시점 성숙도 확인 필요) |

**정직한 한계(오늘 확인)**: WASI 0.2는 **스레딩 미해결**, native async는 0.3에서 오고,
일반 백엔드 마이크로서비스는 아직 현실적 타깃이 아니다. ⟹ **장기 실행·동시성 기관은 당분간
네이티브로 두고, WASM에는 순수 변환형 확장**(distiller, 오라클, 정책 술어, 포맷 어댑터)만
올린다. 이 경계를 지금 문서에 박아두지 않으면 나중에 "WASM으로 다 하자"가 나온다.

## 5. P4 증명 — 오라클은 설득당하면 안 된다

우리 논지 전체가 *"외부 검증"*인데 현재 오라클은 `pytest` + **내가 쓴 Python 검사**다.
생태계에서는 그게 안 통한다 — 참여자가 자기 검사를 쓰면 자기 채점이 된다.

| 대상 | 도구 | 왜 |
|---|---|---|
| 원장 불변식(추가전용·freshness·supersede) | **Lean 4** | 유한 상태기계라 증명 가능. 실패 시 M0 영수증이 무효가 되는 자리 |
| **lease/takeover 프로토콜** | **TLA+ / Apalache** | **우리가 이미 한 번 틀린 곳**(INV-3 pid-liveness). 동시성 버그는 테스트로 안 잡힌다 |
| 능력 격자 건전성 | Lean 4 또는 Alloy | capability가 확대되지 않음을 증명 |
| 값싼 층 | `proptest`(Rust) · `hypothesis`(Python) | 증명 전 단계의 반례 사냥 |
| 적합성 인증 | 컨테이너 + WASM 하네스로 배포 | 참여자가 **스스로 인증**할 수 있어야 생태계 |

## 6. P6 provisioning — founder가 지목한 지점, 그리고 생태계의 실제 병목

**생태계는 스펙이 아니라 설치 경험으로 성립한다.** 참여자가 우리에게 묻지 않고 노드를
세울 수 있어야 하고, 그 경로가 여러 개여야 한다.

| 채널 | 대상 |
|---|---|
| `uvx` / `pipx` | Python 코어 — 설치 없이 실행 |
| `cargo-dist` 바이너리 + shell installer | 커널 — 런타임 의존성 0 |
| **OCI 이미지** + devcontainer | 재현 가능한 즉시 실행 |
| **Nix flake** | 적합성 실행의 **재현성** — 생태계 속성이지 편의가 아니다 |
| Homebrew tap / apt / winget | 일반 개발자 |
| npm | TS SDK |
| Kubernetes operator · systemd unit · **OpenTofu** provider | 조직 단위 운영 |

**그리고 루프를 닫는 수 하나** — 이게 이 문서에서 가장 마음에 드는 부분이다:

> 우리 **빌드 파이프라인 자체가 첫 번째 적합 참여자**가 된다.
> 릴리스는 in-toto/SLSA provenance를 만들고, Sigstore로 서명하고, 그 증명을 **같은 투명성
> 로그**에 등록해 receipt를 받는다. 즉 *"AIOS를 배포하는 행위"*가 AIOS의 4-튜플을 한 번
> 도는 것이다 — SENSE(태그 푸시) → ACT(빌드) → VERIFY(재현 빌드·서명 검증) →
> SETTLE(투명성 로그 등록 또는 거부).
> **생태계의 첫 사용자는 생태계 자신이어야 한다.** 그러지 못하면 우리가 안 쓰는 것을
> 남에게 파는 것이고, 오늘 하루 종일 잰 실패 모드가 정확히 그것이다.

## 7. 우리가 **쓰지 않을** 것 (스프롤 방지)

임베딩 모델·벡터 DB·에이전트 프레임워크(LangGraph/CrewAI/AutoGen)·스케줄러·오케스트레이터를
직접 만들지 않는다. 우리 자리는 그 위/아래의 **경계와 원장**이다.
