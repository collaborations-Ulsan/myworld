# 7홉과 sheaf — 재봤다 (2026-08-18)

founder: *"graph로 연결돼 있으면 웬만하면 7hop만에 전부 탐색 가능하지 않나? 랜덤으로 retriever
몇 개 뿌리고 n-hop으로 수십억 노드까지? 그리고 sheaf로 코호몰로지를 재서 점점 더 효율적으로?"*

## 1. 7홉 — 절반은 맞고 절반은 정확히 반대다 (실측)

우리 그래프 101,221 연결노드, 평균차수 6.4. 랜덤 시드 5개에서 BFS:

```
seed0   h3:14%   h4:29%   h5:84%   h6:84%   h7:85%   → 포화
seed1   h2: 7%   h3:26%   h4:59%   h5:84%   h7:85%   → 포화
seed2   h1: 2    h2:66    h3:66                       → 죽음
seed3   h1: 2    h2:66    h3:66                       → 죽음
seed4   (seed0과 동일 궤적)
```

**맞는 것**: small-world가 성립한다. 5홉이면 85%에 닿고 7홉에 포화한다.

**반대인 것**: 그게 정확히 **탐색으로 쓸 수 없는 이유**다.

> `h4: 29% → h5: 84%` — **한 홉에 프론티어가 폭발한다.**
> 5홉을 돈다는 것은 코퍼스의 85%를 이미 읽었다는 뜻이고,
> 그건 검색이 아니라 **단계가 추가된 전수 스캔**이다.

수십억 노드로 키우면 이 성질은 **나빠진다**. 도달 가능성은 유지되지만 h5의 절대 크기가
같이 커지므로, "7홉이면 닿는다"는 "7홉 안에 전부 읽어야 한다"와 같은 말이 된다.

**그리고 랜덤 살포에는 측정된 실패 모드가 있다**: 시드 5개 중 **2개가 66노드(0.07%)짜리
성분에 갇혀 죽었다.** 이 표본에서 랜덤 시드 실패율 40%.

⟹ **병목은 도달 가능성이 아니라 순서다.** 그래프가 검색에 주는 값은 *"닿을 수 있나"*가
아니라 *"어느 이웃을 먼저 펼치나"*다. 그러므로 다음 작업은 n-hop 확장이 아니라
**프론티어 우선순위**(중심성·관련도 기반 beam)이고, 그건 홉 수를 늘리지 않고 줄인다.

## 2. sheaf/코호몰로지 — 재개봉이 아니라 새 질문이다, 단 사전이 무겁다

기록을 먼저 확인했다. **DescentNet(sheaf coboundary δ + Hodge split, H¹ obstruction)은
이미 실데이터에서 exhaustive하게 검정됐고 결과는 NEGATIVE였다:**

```
예측 (R0/R1)          DescentNet 신호 = 0
cross-agent 전이 (R2)  base-rate 대비 0
오염 저항 (R3/R4)      H¹ AUC ≤ 0.59 — 무료 tool-entropy 필터 0.66~0.69에 지배당함
살아남은 잔여          H¹은 same-vocab cyclic 모순의 유일 탐지기 (witness AUC 1.00)
                       단 non-dominant. 실제 오염은 H⁰-shape(vocabulary shift)였다
재개 조건              H¹ AUC가 실배포에서 H⁰ baseline을 교차할 때
```

**그런데 그 검정의 대상은 *agent 기억의 오염 탐지*였고, founder가 지금 말한 것은
*그래프 구성·탐색의 효율*이다.** 대상도 목적도 다르므로 **닫힌 결정의 재개봉이 아니라
새 질문**이다. 기록된 재개 조건(H¹ AUC 교차)은 이 질문을 덮지 않는다.

다만 그 negative가 **사전(prior)과 문턱**은 남긴다. 그때 sheaf를 죽인 것은 수학이 틀려서가
아니라 **값싼 baseline이 지배**했기 때문이다. 그래서 게이트는 이렇게 건다:

```
어떤 코호몰로지도 짓기 전에:
  값싼 baseline(중심성 우선순위 · BM25 · 임베딩 근접)이 먼저 구현되고 측정될 것
  sheaf 기반 방법은 그 baseline을 이겨야 존재 정당성을 갖는다
  ← M2의 arm B, M3의 arm B와 같은 구조. 우리가 이미 세 번 쓰는 형태다
```

**이 문서가 제시하는 §1의 측정이 그 baseline의 좌표를 이미 준다**: 개선 대상은
"도달 가능성"이 아니라 "h4→h5에서 29%→84%로 터지는 프론티어"이며, 그것을 줄이는지로 잰다.
